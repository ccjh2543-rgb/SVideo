# 二、博主表（作者元数据表）最优设计
表名：`author` / `user_author`
```sql
CREATE TABLE `author` (
  `author_id` bigint PRIMARY KEY,  // 对应用户ID
  `fans_count` int DEFAULT 0,      // 粉丝总数（核心！判断大小V）
  `last_publish_time` datetime,    // 最后一条视频发布时间（核心！过滤沉默博主）
  `video_count` int DEFAULT 0,     // 总作品数（可选）
  `is_big_v` tinyint DEFAULT 0,    // 预标记是否大V（可选，优化判断）
  `updated_at` datetime
);
```

### 这张表的意义：
把**博主的核心元数据**单独抽离，查询极快、批量查询更快。

# 三、这个表如何让关注流性能爆炸提升？（完整流程）
## 用户打开关注流 → 执行逻辑（优化后）
1. **从关注表查出：我关注了哪些博主 ID**
   `SELECT author_id FROM follow WHERE user_id = ?`
2. **批量查博主表，拿到关键元数据（一次批量查询）**
   `SELECT author_id, fans_count, last_publish_time FROM author WHERE author_id IN (?)`
3. **在内存中做两层过滤（最关键！）**
   - **过滤 1：沉默博主**
     `last_publish_time < 7天前` → **直接跳过，不查视频！**
   - **过滤 2：区分大小博主**
     `fans_count < 10000` → 小博主（读你的 Redis Inbox）
     `fans_count >= 10000` → 大V（读他的 Redis Outbox）
4. **只对「活跃博主」拉取视频**
   剩下可能只有 10%~30% 的博主需要查 Redis
5. **合并排序 → 返回**
