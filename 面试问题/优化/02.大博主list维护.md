# 一、大博主的 Redis 缓存怎么设计？（超简单）
给**每个大博主维护一个独立的 Redis List**，只存**最新 5~10 条视频ID**（极小，无任何大Key风险）

### Key 设计
```redis
video:author:big:{博主ID}
```

### 维护方式（和关注流完全一致）
大博主发布视频时，只做2个操作：
```redis
# 1. 头部插入新视频ID
LPUSH video:author:big:10086  88888

# 2. 裁剪，只保留最新5条（永远不膨胀）
LTRIM video:author:big:10086  0  4
```

# 二、用户刷关注流：全程 Redis，零 MySQL 查询
## 完整流程（最终版）
1. **拆分关注列表**
   把用户关注的人，分成：**小博主** + **大博主**
2. **读小博主视频**
   直接取用户自己的 Redis 关注流：
   ```redis
   LRANGE follow:feed:1001 0 9
   ```
3. **批量读大博主视频（核心优化）**
   用 **Redis Pipeline 管道** 一次性批量读取所有关注的大博主的缓存：
   ```redis
   # 批量获取3个大博主的最新5条视频
   LRANGE video:author:big:10086 0 4
   LRANGE video:author:big:10087 0 4
   LRANGE video:author:big:10088 0 4
   ```
   ✅ Pipeline 批量执行，**只发一次网络请求**，性能极致
4. **内存合并排序**
   把小博主 + 大博主的视频，按**发布时间戳**倒序排序
5. **返回前10条**给前端
