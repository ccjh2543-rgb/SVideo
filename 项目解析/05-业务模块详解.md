## 🧑 模块一：Account 账号系统

### 7个接口清单

| 接口 | 路由 | 是否需要登录 |
|------|------|-----------|
| 注册 | POST /account/register | ❌ 不需要 |
| 登录 | POST /account/login | ❌ 不需要 |
| 改密码 | POST /account/changePassword | ✅ 需要 |
| 按ID查用户 | POST /account/findByID | ❌ 不需要 |
| 按用户名查用户 | POST /account/findByUsername | ❌ 不需要 |
| 改名 | POST /account/rename | ✅ 需要 |
| 登出 | POST /account/logout | ✅ 需要 |

---

### 登录接口执行流程

```
用户输入账号密码
    ↓
1. 参数校验：账号密码是否为空
    ↓
2. 根据用户名查数据库
    ↓
3. bcrypt 比对密码哈希
    ↓
4. 生成新的 JWT Token
    ↓
5. 更新数据库的 token 字段
    ↓
6. 写 Redis 缓存（token -> accountId），TTL 24小时
    ↓
返回 Token 给前端
```

✨ **设计亮点**：
- 密码永远不返回，bcrypt 哈希不可逆
- 每次登录生成新 Token，旧 token 自动失效
- Redis 缓存 + MySQL 兜底双写

---

### 登出接口执行流程

```
用户点登出
    ↓
1. JWT 鉴权拿到 accountId
    ↓
2. 清空数据库里的 token 字段
    ↓
3. 删除 Redis 缓存里的 token
    ↓
返回成功
```

## 🎬 模块二：Video 视频系统

### 5个接口清单

| 接口 | 路由 | 是否需要登录 |
|------|------|-----------|
| 上传视频文件 | POST /video/uploadVideo | ✅ 需要 |
| 上传封面图片 | POST /video/uploadCover | ✅ 需要 |
| 发布视频 | POST /video/publish | ✅ 需要 |
| 按作者ID查视频列表 | POST /video/listByAuthorID | ❌ 不需要 |
| 视频详情 | POST /video/getDetail | ❌ 不需要 |

---

### 上传文件执行流程

```
用户选择 MP4 文件
    ↓
1. JWT 鉴权
    ↓
2. 文件大小校验：≤ 200MB
    ↓
3. 后缀校验：只能 .mp4
    ↓
4. 生成随机16位文件名
    ↓
5. 按日期/用户ID分目录存储
    ↓
6. 写入本地磁盘
    ↓
返回静态文件 URL
```

📁 **目录结构**：
```
.run/uploads/videos/{用户ID}/{日期}/{随机文件名}.mp4
```

---

### 发布视频执行流程

```
用户填标题+描述，点发布
    ↓
1. JWT 鉴权
    ↓
2. 写入 videos 表
    ↓
3. 写入 outbox_msgs 发件箱
    ↓
4. 后台 Worker 扫发件箱
    ↓
5. 投递到粉丝 Timeline ZSET
    ↓
返回视频对象
```

✨ **设计亮点**：发件箱模式保证了
- 接口响应快（只写两张表）
- 就算 MQ 挂了，后台 Worker 也能补偿投递

## ❤️ 模块三：Like 点赞系统

### 4个接口清单

| 接口 | 路由 | 是否需要登录 |
|------|------|-----------|
| 点赞 | POST /like/like | ✅ 需要 + 限流 |
| 取消点赞 | POST /like/unlike | ✅ 需要 + 限流 |
| 是否点赞 | POST /like/isLiked | ✅ 需要 |
| 我赞过的视频 | POST /like/listMyLikedVideos | ✅ 需要 |

---

### 点赞接口完整执行流程

```
用户点小心心 ❤️
    ↓
1. JWT 鉴权
    ↓
2. 限流检查：30次/分钟
    ↓
3. ⭐ 尝试发 MQ 异步消息
    ↓
4. ❌ MQ 发失败了？降级！直接写 MySQL
    ↓
5. 发热度增量事件：likes_count +1
    ↓
6. 删除视频详情缓存
    ↓
返回成功
```

✨ **设计亮点**：
- 正常走 MQ 异步，响应 < 10ms
- MQ 挂了自动降级直写，用户无感知
- 永远不会出现「点了赞但是数据没写进去」

## 📰 模块六：Feed 信息流系统（最复杂！）

### 4个接口清单

| 接口 | 路由 | 鉴权方式 |
|------|------|---------|
| 最新时间流 | POST /feed/listLatest | Soft 软鉴权 |
| 点赞数排序 | POST /feed/listLikesCount | Soft 软鉴权 |
| 热度排行榜 | POST /feed/listByPopularity | Soft 软鉴权 |
| 我关注人的视频 | POST /feed/listByFollowing | Hard 硬鉴权 |

---

### Feed 流混合架构

```
用户刷新首页
    ↓
时间游标 > 5分钟？→ 热数据？
    ↓ Yes
走 Redis ZSET 热度排行榜 → 查 20 个 videoID
    ↓
批量查视频详情 → 补齐点赞/评论数据
    ↓
返回给用户

    ↓ No
冷数据 → 直接走 MySQL ORDER BY create_time DESC
    ↓
单飞 + 分布式锁防击穿
```

✨ **设计亮点**：
- 冷数据 / 热数据 分层处理
- 软鉴权：游客也能刷首页，登录了看关注流
- ZSET 做排行榜天然有序，分页简单

## 💡 所有业务模块的共性设计

### 1. 接口返回值统一

成功：
```json
{
    "data": { ... }
}
```

失败：
```json
{
    "error": "错误信息"
}
```

### 2. 所有写接口都有限流

防刷、防攻击是默认选项！

### 3. 所有 MQ 都有降级策略

宁可接口慢一点，也绝不能让用户操作失败！
