# 01 - 项目架构与目录结构详解

> 零基础学习指南 · 第一篇：先看懂森林，再研究树木

## 📋 项目全景概览

这是一个**工业级标准的 Go 短视频 Feed 系统后端项目**，采用了大厂标准的分层架构设计。

***

## 🗺️ 整体目录结构

```
feedsystem_video_go-main/
├── backend/                    # 🔴 后端核心 (Go)
│   ├── cmd/                    # 程序入口
│   ├── configs/                # 配置文件
│   └── internal/               # 业务代码
│       ├── account/            # 🧑 用户账号模块
│       ├── video/              # 🎬 视频 + 点赞 + 评论
│       ├── social/             # 👥 关注系统
│       ├── feed/               # 📰 Feed 信息流
│       ├── http/               # 🛣️ 路由配置
│       ├── middleware/         # 🛡️ 中间件
│       ├── db/                 # 💾 数据库连接
│       ├── worker/             # 👷 异步消费者
│       └── config/             # ⚙️ 配置加载
├── frontend/                   # 🟢 前端 (Vue)
├── picture/                    # 📐 设计文档图片
├── docker-compose.yml          # 🐳 Docker 一键启动
└── README.md                   # 📖 项目说明
```

***

## 🔴 深入后端目录详解

### 1. cmd/ - 程序大门

| 文件                   | 作用                    |
| -------------------- | --------------------- |
| `cmd/main.go`        | API 服务入口，程序启动的第一行代码   |
| `cmd/worker/main.go` | Worker 消费者入口，异步消费消息队列 |

💡 **零基础理解**：就像你家的大门，回家第一个走这里。

***

### 2. configs/ - 通讯录/电话本

| 文件                          | 适用场景          | MySQL端口 | Redis端口 |
| --------------------------- | ------------- | ------- | ------- |
| `config.yaml`               | ✅ **本地原生运行**  | 3306    | 6379    |
| `config.compose-local.yaml` | Docker依赖+本地Go | 3308    | 6378    |
| `config.docker.yaml`        | 完全容器化运行       | 容器内通信   | 容器内通信   |

💡 **零基础理解**：就像你手机里的通讯录，写着 MySQL 住哪，Redis 住哪。

***

### 3. internal/ - 大楼主体（99%的代码在这里）

#### 3.1 六大业务模块

| 模块目录       | 负责功能              | 对应前端页面       |
| ---------- | ----------------- | ------------ |
| `account/` | 注册、登录、改密码、改名、登出   | 登录页、注册页、个人中心 |
| `video/`   | 上传视频、封面、发布视频、视频列表 | 视频上传页、我的视频   |
| `video/`   | 点赞、取消赞、我赞过的视频     | 视频下面的小心心 ❤️  |
| `video/`   | 发评论、删评论、评论列表      | 视频评论区        |
| `social/`  | 关注、取关、我的粉丝、我关注的人  | 用户主页关注按钮     |
| `feed/`    | 最新视频、最热视频、我关注人的视频 | 首页刷新的视频流     |

***

#### 3.2 每个业务模块下的 4 个标准文件

| 文件名          | 中文  | 只做什么             | ❌ 绝对不能做什么 |
| ------------ | --- | ---------------- | --------- |
| `handler.go` | 处理器 | 收参数、校验、调用Service | 写SQL      |
| `service.go` | 业务层 | 写业务逻辑，先做什么后做什么   | 直接写SQL    |
| `repo.go`    | 仓库层 | 只做SQL增删改查        | 写业务逻辑     |
| `entity.go`  | 实体  | 和数据库表一一对应的结构体    | 任何逻辑      |

✨ **这就是行业标准三层架构！**

```
前端请求 → Handler → Service → Repository → MySQL
```

***

#### 3.3 middleware/ - 大楼保安

| 中间件          | 作用   | 比喻                    |
| ------------ | ---- | --------------------- |
| `jwt/`       | 鉴权   | 🚪 小区门禁，没带门禁卡不让进      |
| `ratelimit/` | 限流   | 🕒 排队机，1分钟只能进30人      |
| `redis/`     | 缓存   | 🧊 冰箱，常用的东西放冰箱不用每次去超市 |
| `rabbitmq/`  | 消息队列 | 📮 邮局信箱，信放进去慢慢送       |

***

#### 3.4 worker/ - 后台默默干活的工人（异步处理）

| Worker           | 做什么        | 为什么要异步？          |
| ---------------- | ---------- | ---------------- |
| LikeWorker       | 后台把点赞写进数据库 | 用户点完❤️马上返回，不用等写库 |
| CommentWorker    | 后台把评论写进数据库 | 用户发完评论马上显示，不用等写库 |
| SocialWorker     | 后台把关注写进数据库 | 点关注马上生效，后台慢慢写    |
| PopularityWorker | 后台更新视频热度排行 | 在后台默默更新热榜        |

***

#### 3.5 其他基础设施

| 目录                       | 作用                     |
| ------------------------ | ---------------------- |
| `http/router.go`         | 楼层导览图：哪个URL交给哪个Handler |
| `db/db.go`               | 小区总电表：MySQL连接和自动建表     |
| `observability/pprof.go` | 电表水表：性能监控              |
| `.run/uploads/`          | 文件存储：用户上传的视频和封面        |

***

## 📊 项目设计亮点总结

| 设计模式                            | 好处                        |
| ------------------------------- | ------------------------- |
| 三层架构 Handler-Service-Repository | 明天换数据库只改 repo.go          |
| 优雅降级                            | Redis/RabbitMQ 挂了不崩溃，只是变慢 |
| 异步解耦                            | 响应用户更快，削峰填谷               |
| 中间件分层                           | 所有接口统一鉴权/限流/日志            |
