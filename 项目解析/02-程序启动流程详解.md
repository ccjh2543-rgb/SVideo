## 💡 逐行精读详解

---

### 📝 第一步：加载配置文件

```go
// 第18-32行
configPath := os.Getenv("CONFIG_PATH")
if configPath == "" {
    configPath = "configs/config.yaml"    // 默认配置文件
}
cfg, usedDefault, err := config.LoadLocalDev(configPath)
```

#### 零基础解释：

1. 先看看环境变量有没有指定用哪个配置文件
2. 没有的话就默认用 `configs/config.yaml`
3. 把 yaml 文件里的内容都读进来，包括：
   - MySQL 地址、端口、密码
   - Redis 地址、端口、密码
   - RabbitMQ 地址、端口、账号密码
   - 服务启动端口

✅ **开店比喻**：
> 开门前先拿个小本本记下来：
> - 仓库地址：xxx
> - 冰箱位置：xxx
> - 门店号码：8080

---

### 💾 第二步：连接数据库

```go
// 第35-42行
sqlDB, err := db.NewDB(cfg.Database)          // 连接 MySQL
if err := db.AutoMigrate(sqlDB); err != nil {  // ✨ 自动建表！
defer db.CloseDB(sqlDB)                       // 程序退出时自动关门
```

#### ✨ GORM AutoMigrate - 最省心的设计

你**完全不用写 SQL建表语句**！

程序启动时自动检查：
```
✅ accounts 表存在吗？没有就 CREATE TABLE！
✅ videos 表存在吗？没有就 CREATE TABLE！
✅ likes 表？
✅ comments 表？
✅ socials 表？
✅ outbox_msgs 表？
```

6张表一键搞定！

✅ **开店比喻**：
> 你租了个仓库，房东 GORM 免费帮你把所有货架都打好了，
> 你直接放货就行！

#### defer - Go 语言的特色

```go
defer db.CloseDB(sqlDB)
```

字面意思：**推迟执行**

- 不是现在执行
- 而是等整个 main() 函数跑完了，临走前再执行
- 按 Ctrl+C 停止程序时，会先优雅地断开数据库连接

---

### 🧊 第三步：连接 Redis 缓存

```go
// 第45-59行
cache, err := rediscache.NewFromEnv(&cfg.Redis)
if err != nil {
    cache = nil    // ❌ 连不上就不用了！降级！
} else {
    if err := cache.Ping(pingCtx); err != nil {
        cache = nil  // ❌ 挂了也不用！降级！
    } else {
        log.Printf("Redis connected (cache enabled)")
    }
}
```

#### ✨ 高可用设计 1 - 优雅降级

这是整个项目最值得学习的设计之一！

| 场景 | 处理方式 |
|------|---------|
| ✅ Redis 能连上 | 用缓存，性能飞起 |
| ❌ Redis 连不上 | 不用缓存，直接查 MySQL |

**永远不会因为 Redis 挂了导致服务崩溃！**

✅ **开店比喻**：
> 冰箱坏了怎么办？大不了我不用冰箱！
> 虽然菜不冰了，但生意照做！客人来了照样招待！

---

### 📮 第四步：连接 RabbitMQ

```go
// 第62-68行
rmq, err := rabbitmq.NewRabbitMQ(&cfg.RabbitMQ)
if err != nil {
    rmq = nil    // ❌ 连不上就不用！降级！
}
```

#### ✨ 高可用设计 2 - 还是优雅降级

和 Redis 一模一样的设计！

| 场景 | 处理方式 |
|------|---------|
| ✅ MQ 能连上 | 发消息异步消费，响应飞快 |
| ❌ MQ 连不上 | 不用MQ，同步直接写 MySQL |

**永远不会因为 RabbitMQ 挂了导致服务崩溃！**

✅ **开店比喻**：
> 快递员罢工了怎么办？大不了我自己骑自行车送货！
> 虽然慢一点，但生意照做！

---

### 🔧 第五步：pprof 性能监控

```go
// 第70-77行
pprofServer, err := observability.NewPprofServer(...)
```

#### 零基础解释

给你的程序装个「行车记录仪」：
```
http://localhost:6060/debug/pprof
```

以后程序慢了、卡了、崩了，就能回查：
- CPU 跑满了吗？
- 内存泄露了吗？
- 哪个函数执行最慢？
- 哪个地方锁竞争？

开发老手必备神器！

---

### 🛣️ 第六步：设置路由 - 接线板

```go
// 第80行
r := apphttp.SetRouter(sqlDB, cache, rmq)
```

这是整个项目的「接线板」！

把三个工具都递给前台小姐：
- sqlDB：数据库连接（去仓库取货的钥匙）
- cache：Redis 缓存（开冰箱的钥匙）
- rmq：消息队列（寄快递的钥匙）

前台小姐拿到这三把钥匙，就知道怎么接待客人了。

---

### 🚀 第七步：开门营业！

```go
// 第82-85行
log.Printf("Server is running on port %d", cfg.Server.Port)
if err := r.Run(":" + strconv.Itoa(cfg.Server.Port)); err != nil {
    log.Fatalf("Failed to run server: %v", err)
}
```

程序就卡在这一行了！
- 开始监听 8080 端口
- 有人访问就交给对应的 Handler 处理
- 直到你按 Ctrl+C 才停止

## 💡 启动流程中的 3 个牛逼设计

---

### 设计 1：依赖分级 - 只有 MySQL 是必须的

| 依赖 | 可以没有吗 | 崩溃吗 | 影响 |
|------|----------|-------|------|
| MySQL | ❌ 必须 | ✅ 崩溃 | 没仓库开不了店 |
| Redis | ✅ 可选 | ❌ 不崩 | 只是变慢一点 |
| RabbitMQ | ✅ 可选 | ❌ 不崩 | 只是接口变慢 |

这才是真正的「高可用架构」！

---

### 设计 2：错误处理 - 能不崩就不崩

只有 MySQL 连不上才会 `log.Fatal` 崩溃退出。

其他所有依赖失败的处理方式都是：
```go
log.Printf("XXX 连不上，降级运行")
xxx = nil   // 置空，后续代码会判断并降级
```

崩溃是后端开发的大忌！

---

### 设计 3：资源清理 - defer 优雅退出

```go
defer db.CloseDB(sqlDB)
defer cache.Close()
defer rmq.Close()
defer pprofServer.Close()
```

程序停止时，会按照先进后出的顺序，优雅地断开所有连接，清理所有资源。

不会杀进程搞的一地鸡毛！
