# 05 - Redis Lua 令牌桶限流

## 1. 改造前的问题

改造前 `ratelimit.Limit` 是固定窗口计数器：

```text
INCR key
if count == 1: PEXPIRE key window
count > max -> 429
```

问题：

- 不是令牌桶，无法平滑控制速率。
- 窗口边界会突刺：窗口最后 1 秒和下一个窗口第 1 秒可以打出 2 倍流量。
- 限流中间件没有挂到任何路由。

改造后：

- 使用 Redis Hash + Lua 实现真正的令牌桶。
- 支持容量（突发）和补充速率（持续速率）。
- 多实例共享同一份 Redis 状态。
- 已挂到登录、注册、发布、点赞、评论、关注、Feed 等接口。

---

## 2. 令牌桶原理

令牌桶有两个参数：

| 参数 | 含义 |
|---|---|
| `capacity` | 桶容量，允许的最大突发请求数 |
| `refillPerSecond` | 每秒补充的令牌数 |

流程：

```text
1. 桶初始有 capacity 个令牌
2. 请求到来时尝试取 1 个令牌
3. 取到 -> 放行
4. 取不到 -> 429
5. 随时间按 refillPerSecond 补充，最多补到 capacity
```

示意图：

```text
容量 10，速率 1/s

突发 10 个请求 -> 全部放行，桶空
等待 3 秒      -> 补充 3 个令牌
再来 3 个请求  -> 全部放行
第 4 个请求    -> 429
```

---

## 3. Redis 数据结构

使用一个 Hash 保存桶状态：

```text
key = feedsystem:ratelimit:{scene}:{subject}

HSET key tokens <当前令牌数>
HSET key ts     <上次补充时间，毫秒>
PEXPIRE key <ttl>
```

示例：

```text
feedsystem:ratelimit:account:login:127.0.0.1
  tokens = 7.35
  ts     = 1760000000000
```

Key 设计：

| 场景 | subject | 示例 |
|---|---|---|
| 登录/注册 | IP | `feedsystem:ratelimit:account:login:127.0.0.1` |
| 发布/点赞/评论 | accountID | `feedsystem:ratelimit:video:publish:42` |
| Feed | accountID 或 IP | `feedsystem:ratelimit:feed:read:account:42` |

## 4. Lua 脚本

文件：`backend/internal/middleware/redis/redis.go`

```lua
local key = KEYS[1]
local capacity = tonumber(ARGV[1])
local refill = tonumber(ARGV[2])
local now = tonumber(ARGV[3])
local ttl = tonumber(ARGV[4])

local data = redis.call("HMGET", key, "tokens", "ts")
local tokens = tonumber(data[1])
local ts = tonumber(data[2])
if tokens == nil then
  tokens = capacity
  ts = now
end

local delta = math.max(0, now - ts) / 1000.0
tokens = math.min(capacity, tokens + delta * refill)

local allowed = 0
if tokens >= 1 then
  tokens = tokens - 1
  allowed = 1
end

redis.call("HSET", key, "tokens", tokens, "ts", now)
redis.call("PEXPIRE", key, ttl)
return {allowed, math.floor(tokens)}
```

关键点：

1. **整个“读取-补充-扣减-写回”在 Redis 单线程内原子执行**，不会出现并发超发。
2. `tokens == nil` 表示首次请求，桶初始化为满容量。
3. `delta = max(0, now - ts)` 防止时钟回拨导致令牌减少。
4. `min(capacity, ...)` 防止令牌超过容量。
5. 每次请求都刷新 TTL，桶空闲一段时间后自动删除。

## 6. 中间件

文件：`backend/internal/middleware/ratelimit/token_bucket.go`

```go
func TokenBucket(
    cache *rediscache.Client,
    keyPrefix string,
    cfg TokenBucketConfig,
    keyFunc KeyFunc,
) gin.HandlerFunc {
    return func(c *gin.Context) {
        if cache == nil || keyFunc == nil || cfg.Capacity <= 0 || cfg.RefillPerSecond <= 0 {
            c.Next()
            return
        }

        subject, ok := keyFunc(c)
        if !ok || subject == "" {
            c.Next()
            return
        }

        ttl := cfg.TTL
        if ttl <= 0 {
            ttl = DefaultBucketTTL(cfg.Capacity, cfg.RefillPerSecond)
        }

        allowed, remaining, err := cache.TakeToken(
            c.Request.Context(),
            buildKey(keyPrefix, subject),
            cfg.Capacity,
            cfg.RefillPerSecond,
            ttl,
        )
        if err != nil {
            c.Next()
            return
        }
        if !allowed {
            c.Header("Retry-After", "1")
            c.Header("X-RateLimit-Remaining", fmt.Sprintf("%d", remaining))
            c.AbortWithStatusJSON(http.StatusTooManyRequests, gin.H{
                "error": "too many requests",
            })
            return
        }

        c.Header("X-RateLimit-Remaining", fmt.Sprintf("%d", remaining))
        c.Next()
    }
}
```

## 7. 限流维度

### 7.1 按 IP

```go
func KeyByIP(c *gin.Context) (string, bool) {
    ip := strings.TrimSpace(c.ClientIP())
    if ip == "" {
        return "", false
    }
    return ip, true
}
```

适合：

- 登录
- 注册
- 刷新 Token
- 公开查询

### 7.2 按账号

```go
func KeyByAccount(c *gin.Context) (string, bool) {
    accountID, err := jwt.GetAccountID(c)
    if err != nil || accountID == 0 {
        return "", false
    }
    return strconv.FormatUint(uint64(accountID), 10), true
}
```

适合：

- 发布视频
- 上传文件
- 点赞
- 评论
- 关注

### 7.3 账号优先，匿名回退 IP

```go
func KeyByAccountOrIP(c *gin.Context) (string, bool) {
    if accountID, err := jwt.GetAccountID(c); err == nil && accountID > 0 {
        return fmt.Sprintf("account:%d", accountID), true
    }
    ip := c.ClientIP()
    if ip == "" {
        return "", false
    }
    return "ip:" + ip, true
}
```

适合 Feed：登录用户按账号，游客按 IP。

## 9. TTL 计算

```go
func DefaultBucketTTL(capacity int64, refillPerSecond float64) time.Duration {
    seconds := math.Ceil(float64(capacity) / refillPerSecond)
    if seconds < 60 {
        seconds = 60
    }
    return time.Duration(seconds) * time.Second
}
```

目的：

- 桶完全恢复所需时间作为 TTL。
- 至少保留 60 秒，避免频繁重建。
- 空闲桶自动删除，防止 Redis Key 无限增长。

## 10. 降级策略

令牌桶是“保护组件”，不能成为单点故障。

当前策略：

```text
Redis 不可用
-> TakeToken 返回 error
-> 中间件 c.Next() 放行
-> 业务继续处理
```

即 **fail-open**。

原因：

- 限流是为了保护系统，不是为了阻断正常用户。
- Redis 故障时，数据库和 MQ 仍然是主要依赖。
- 如果 fail-close，Redis 一挂整个系统不可用。

风险：

- Redis 故障期间可能被刷流量。
- 生产环境应配合网关限流、WAF、监控告警。

## 11. 边界情况

| 场景 | 行为 |
|---|---|
| 首次请求 | `tokens=nil`，初始化为满容量 |
| 突发流量 | 最多消耗 `capacity` 个令牌 |
| 持续流量 | 超过 `refillPerSecond` 后逐渐 429 |
| Redis 故障 | fail-open，放行 |
| 配置非法 | fail-open，放行 |
| `keyFunc` 取不到 subject | fail-open，放行 |
| 时间回拨 | `max(0, now-ts)`，不会出现负补充 |
| 多实例部署 | 共享 Redis，状态一致 |
| Key 过期 | 下次请求重新初始化为满桶 |
| 代理 IP | `ClientIP` 依赖 Gin 的代理配置；当前 `SetTrustedProxies(nil)` |
| 账号不存在 | 鉴权先失败，不会进入限流 |
| 登录接口被刷 | 按 IP 限制，攻击者换 IP 可绕过，需要网关/WAF 配合 |

### 11.1 代理 IP 问题

当前：

```go
r.SetTrustedProxies(nil)
```

表示不信任任何代理头，`ClientIP` 使用直连 IP。

如果部署在 Nginx 后面：

- 所有请求的直连 IP 都是 Nginx 的 IP。
- 按 IP 限流会把所有用户当成同一个 IP。

生产环境需要：

```go
r.SetTrustedProxies([]string{"10.0.0.0/8"})
```

并确保 Nginx 正确设置 `X-Forwarded-For`。

### 11.2 限流与鉴权顺序

正确顺序：

```text
JWTAuth -> TokenBucket -> Handler
```

如果反过来：

```text
TokenBucket -> JWTAuth -> Handler
```

`KeyByAccount` 拿不到 `accountID`，会直接 fail-open，账号维度限流失效。

## 13. 后续优化

1. 把限流参数移到配置文件或配置中心，而不是硬编码在 Router。
2. 增加按接口分组的默认策略，避免每个路由手写参数。
3. 增加限流指标：放行数、拒绝数、Redis 错误数。
4. 对登录接口增加“账号 + IP”双维度限流，防止撞库。
5. 结合网关层限流，形成多层防护。
