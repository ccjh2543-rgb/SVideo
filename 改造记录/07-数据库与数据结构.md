## 2. accounts 表

存量表结构：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint unsigned | 主键 |
| `username` | varchar(255) | 用户名，唯一 |
| `password` | varchar(255) | bcrypt 哈希 |
| `token` | varchar(255) | 旧版单 Token 字段，当前认证不再依赖 |

GORM 模型：

```go
type AccountModel struct {
    ID       uint   `gorm:"primaryKey"`
    Username string `gorm:"unique"`
    Password string `gorm:"column:password"`
    Token    string `gorm:"column:token"`
}

func (AccountModel) TableName() string {
    return "accounts"
}
```

说明：

- 领域实体 `domain/account.Account` 不包含 `Token`。
- `token` 字段只为兼容旧代码保留，新的双 Token 认证不再读写它。
- 后续可以删除 `token` 字段。

## 3. refresh_tokens 表

### 3.1 表结构

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | bigint unsigned | PK | 自增主键 |
| `account_id` | bigint unsigned | index, not null | 所属账号 |
| `jti` | varchar(64) | uniqueIndex, not null | Refresh Token 唯一 ID |
| `family_id` | varchar(64) | index, not null | 登录会话 ID |
| `expires_at` | datetime | not null | 过期时间 |
| `revoked_at` | datetime | index, nullable | 撤销时间，null 表示有效 |
| `created_at` | datetime | autoCreateTime | 创建时间 |

GORM 模型：

```go
type RefreshTokenModel struct {
    ID        uint       `gorm:"primaryKey"`
    AccountID uint       `gorm:"index;not null"`
    JTI       string     `gorm:"column:jti;uniqueIndex;size:64;not null"`
    FamilyID  string     `gorm:"column:family_id;index;size:64;not null"`
    ExpiresAt time.Time  `gorm:"not null"`
    RevokedAt *time.Time `gorm:"index"`
    CreatedAt time.Time  `gorm:"autoCreateTime"`
}

func (RefreshTokenModel) TableName() string {
    return "refresh_tokens"
}
```

### 3.2 索引设计

| 索引 | 作用 |
|---|---|
| `jti` 唯一索引 | 刷新时按 JTI 精确定位；防止重复写入 |
| `account_id` 索引 | 改密、全端登出时撤销账号全部 Token |
| `family_id` 索引 | 重放检测时撤销整个登录会话 |
| `revoked_at` 索引 | 查询有效 Token、清理任务 |

### 3.3 对应 SQL

GORM AutoMigrate 生成的结构近似：

```sql
CREATE TABLE refresh_tokens (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  account_id BIGINT UNSIGNED NOT NULL,
  jti VARCHAR(64) NOT NULL,
  family_id VARCHAR(64) NOT NULL,
  expires_at DATETIME NOT NULL,
  revoked_at DATETIME NULL,
  created_at DATETIME NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_refresh_tokens_jti (jti),
  KEY idx_refresh_tokens_account_id (account_id),
  KEY idx_refresh_tokens_family_id (family_id),
  KEY idx_refresh_tokens_revoked_at (revoked_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

实际索引名由 GORM 生成，以数据库为准。

## 4. 数据生命周期

### 4.1 登录

```text
accounts 查询用户
-> 签发 TokenPair
-> INSERT refresh_tokens (jti1, familyA, expires_at)
```

### 4.2 刷新

```text
UPDATE refresh_tokens SET revoked_at = NOW()
WHERE jti = jti1 AND revoked_at IS NULL
-> INSERT refresh_tokens (jti2, familyA, expires_at)
```

### 4.3 重放

```text
SELECT * FROM refresh_tokens WHERE jti = jti1
-> revoked_at != null
-> UPDATE refresh_tokens SET revoked_at = NOW()
   WHERE family_id = familyA AND revoked_at IS NULL
```

### 4.4 登出

```text
UPDATE refresh_tokens SET revoked_at = NOW()
WHERE family_id = familyA AND revoked_at IS NULL
```

### 4.5 改密 / 全端登出

```text
UPDATE refresh_tokens SET revoked_at = NOW()
WHERE account_id = ? AND revoked_at IS NULL
```

### 4.6 改名

```text
更新 accounts.username
-> 撤销该账号全部 refresh_tokens
-> 签发新 TokenPair
-> INSERT 新 refresh_tokens
```

## 5. 为什么选择“数据库保存完整记录”

对比两种方案：

| 方案 | 优点 | 缺点 |
|---|---|---|
| 只存 Redis | 快、实现简单 | Redis 重启丢失，无法审计 |
| 只存 MySQL | 持久、可审计 | 每次刷新多一次数据库查询 |
| MySQL + Redis 缓存 | 兼顾持久性和性能 | 实现复杂，需要处理一致性 |

当前选择：**MySQL 保存完整记录**。

原因：

- 刷新频率远低于业务请求，数据库压力可控。
- 重放检测需要可靠的持久化状态。
- 便于审计和排查。
- Redis 缓存可以在后续阶段作为性能优化加入。

## 6. 领域实体与 GORM 模型分离

### 6.1 领域实体

```go
type RefreshToken struct {
    ID        uint
    AccountID uint
    JTI       string
    FamilyID  string
    ExpiresAt time.Time
    RevokedAt *time.Time
    CreatedAt time.Time
}
```

没有 GORM 标签。

### 6.2 转换

仓储负责转换：

```go
model := &RefreshTokenModel{
    AccountID: token.AccountID,
    JTI:       token.JTI,
    FamilyID:  token.FamilyID,
    ExpiresAt: token.ExpiresAt,
    RevokedAt: token.RevokedAt,
}
```

查询：

```go
return &domainaccount.RefreshToken{
    ID:        model.ID,
    AccountID: model.AccountID,
    JTI:       model.JTI,
    FamilyID:  model.FamilyID,
    ExpiresAt: model.ExpiresAt,
    RevokedAt: model.RevokedAt,
    CreatedAt: model.CreatedAt,
}, nil
```

好处：

- 领域层不感知表名、列名、索引。
- 修改数据库结构时只影响基础设施层。

## 8. 数据清理

当前每次登录和刷新都会新增记录，没有自动清理。

建议 SQL：

```sql
-- 删除过期超过 7 天的记录
DELETE FROM refresh_tokens
WHERE expires_at < NOW() - INTERVAL 7 DAY;
```

或者：

```sql
-- 删除已撤销超过 30 天的记录
DELETE FROM refresh_tokens
WHERE revoked_at IS NOT NULL
  AND revoked_at < NOW() - INTERVAL 30 DAY;
```

建议用定时任务每天执行，避免表无限增长。

## 9. 边界情况

| 场景 | 行为 |
|---|---|
| 同一 JTI 重复插入 | `jti` 唯一索引报错 |
| 用户名重复 | `accounts.username` 唯一索引报错，映射为 409 |
| 并发刷新 | `RevokeIfActive` 条件更新保证只有一个成功 |
| 记录已过期 | 刷新时返回 401 |
| 记录已撤销 | 触发 Family 撤销 |
| 账号被删除 | 刷新时 `FindByID` 失败，返回 401 |
| 数据库不可用 | 登录/刷新失败，返回 500 |
| 时间字段为 NULL | `RevokedAt` 使用 `*time.Time` |
| 表数据量增长 | 需要定期清理任务 |

### 9.1 为什么不物理删除撤销记录

保留 `revoked_at` 的原因：

- 重放检测需要知道“这个 JTI 曾经存在且被撤销”。
- 如果直接删除，旧 Token 再次出现时会被当成“未知 JTI”，无法区分是伪造还是重放。
- 保留记录便于审计。

代价是表会增长，需要用清理任务控制。

### 9.2 索引与写入放大

每次刷新会：

- 更新一条旧记录（写 `revoked_at`）。
- 插入一条新记录。

`jti`、`family_id`、`account_id` 都有索引，写入会有一定放大，但刷新频率低，可以接受。

## 10. 后续优化

1. 增加 `refresh_tokens` 的定时清理任务。
2. 增加 Redis 缓存：`auth:refresh:{jti}`，减少数据库查询。
3. 增加 `user_agent`、`ip` 字段，用于登录设备管理。
4. 增加 `last_used_at`，用于识别长期未使用的会话。
5. 生产环境改用显式 migration 工具，避免 AutoMigrate 的不确定性。
