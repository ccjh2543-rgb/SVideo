## 2. 已知限制

### 2.1 Access Token 不能立即撤销

当前 Access Token 是无状态 JWT，登出/改密后：

- Refresh Token 立即失效。
- Access Token 在剩余 15 分钟内仍可能有效。

如果需要立即失效，可以增加 Redis 黑名单：

```text
key: auth:access:revoked:{jti}
value: 1
TTL: Access Token 剩余有效期
```

每次 `JWTAuth` 解析后检查：

```go
if revoked, _ := cache.Exists(ctx, "auth:access:revoked:"+claims.JTI); revoked {
    return 401
}
```

代价：

- 每个请求多一次 Redis 查询。
- Redis 故障时需要决定 fail-open 还是 fail-close。

### 2.2 Redis 刷新令牌缓存未实现

当前 Refresh Token 只存 MySQL。

每次刷新：

```text
SELECT refresh_tokens WHERE jti = ?
UPDATE refresh_tokens SET revoked_at = ?
INSERT refresh_tokens
```

刷新频率低，数据库压力可控。

后续可以增加：

```text
auth:refresh:{jti} -> JSON(accountID, familyID, expiresAt, revoked)
TTL: 7 天
```

注意缓存一致性：

- 撤销时删除缓存。
- 撤销 Family 时删除该 Family 下所有 JTI 缓存。
- 数据库仍然是最终真相。

### 2.3 改名/改密没有跨仓储事务

当前流程：

```text
更新账号
-> 撤销 Token
-> 签发新 Token
-> 写入新 Refresh Token
```

如果中间步骤失败，可能出现部分成功。

改进方案：

1. 应用层 Unit of Work。
2. 把账号更新和 Token 撤销放入同一个数据库事务。
3. 失败时回滚并返回错误。

### 2.4 旧模块仍在使用旧账号包

`CommentHandler` 仍通过旧 `AccountService.FindByID` 查询用户名。

影响：

- 每次发评论多一次数据库查询。
- 新旧账号模块并存，目录不够纯粹。

改进：

- 评论 Handler 直接使用 `jwt.GetUsername(c)`。
- 删除旧 `internal/account` 包。
- 把 video/social/feed 迁移到 DDD。

### 2.5 限流参数硬编码

当前参数写在 `router.go`：

```go
Capacity: 10, RefillPerSecond: 0.2
```

改进：

```yaml
ratelimit:
  login:
    capacity: 10
    refill_per_second: 1
  publish:
    capacity: 5
    refill_per_second: 0.2
```

### 2.6 压测脚本与限流冲突

`cmd/bench` 会连续注册大量用户。

当前注册限流：

```text
容量 10，0.2/s
```

压测时可能大量 429。

改进：

- 压测环境关闭限流（通过配置开关）。
- 或使用独立压测账号池。
- 或调整压测脚本，降低注册速率。

### 2.7 没有 MySQL 集成测试

当前单元测试使用 fake Repository。

未验证：

- GORM 表名映射。
- 唯一索引冲突。
- `RowsAffected` 行为。
- AutoMigrate 生成结构。

建议增加 integration test。

## 3. 后续改造路线

### Phase 2：推拉结合 Feed + 热榜

目标：

1. 小 V 发布 -> 异步 Fan-out 到粉丝 Inbox ZSET。
2. 大 V 发布 -> 只写自己的 Outbox ZSET。
3. 关注流读取时合并 Inbox + 大 V Outbox。
4. 热榜改为 24 个小时桶 + 线性权重衰减。
5. 修复最新流同毫秒游标边界。

数据结构：

```text
feed:inbox:{userID}       ZSET  member=videoID  score=createTime
feed:outbox:{authorID}    ZSET  member=videoID  score=createTime
hot:video:1h:{yyyyMMddHH} ZSET  member=videoID  score=popularity
hot:video:merge:1h:{asOf} ZSET  合并快照
```

边界：

- MQ 重试导致重复推送 -> ZADD 幂等。
- 大 V 粉丝过多 -> 不推送，读时拉取。
- 取关 -> 读时过滤或异步清理。
- 新关注 -> 回填最近 N 条。
- 自己发布 -> 读时合并自己的内容。
- 同毫秒发布 -> `(score, videoID)` 复合游标。

### Phase 3：缓存加固

目标：

1. 逻辑过期 + 异步重建。
2. 随机 TTL 防雪崩。
3. 布隆过滤器防穿透。
4. 空值缓存。

数据结构：

```text
video:detail:{id}     String  逻辑过期时间 + 数据
bloom:video_ids       Bitmap  视频 ID 布隆过滤器
```

边界：

- 布隆误判 -> 继续查 DB，查不到写空值缓存。
- 逻辑过期 -> 返回旧值，同时异步重建。
- Redis 故障 -> 降级 MySQL。
- 缓存击穿 -> 分布式锁 + SingleFlight。

### Phase 4：MQ 可靠性

目标：

1. 死信队列 DLX/DLQ。
2. 最大重试次数。
3. 消费端 `event_id` 幂等。
4. 接口 `Idempotency-Key`。
5. Outbox 重试字段。

边界：

- 重复消费 -> 幂等表/Redis SETNX。
- 消费失败 -> 重试 3 次后进死信。
- MQ 不可用 -> 同步降级。
- 队列参数变更 -> 需要删除旧队列或使用新队列名。

### Phase 5：WebSocket 通知

目标：

1. `/ws` 建立连接并校验 Access Token。
2. 连接 Hub 按 accountID 管理。
3. Redis Pub/Sub 支持多实例。
4. 点赞、评论、关注、新视频通知。
5. 前端重连和心跳。

边界：

- 未登录/无效 Token -> 拒绝连接。
- 多实例 -> Redis Pub/Sub。
- 断线 -> 客户端重连。
- 消息重复 -> 前端按事件 ID 去重。
- 连接泄漏 -> 心跳超时清理。

## 4. 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| 全量 DDD 重写 | 引入回归 | 渐进式迁移，先账号模块 |
| 双 Token 改造 | 旧 Token 失效 | 发布说明，要求重新登录 |
| 限流过严 | 正常用户被 429 | 参数配置化，监控拒绝率 |
| Redis 故障 | 限流失效、缓存降级 | fail-open + 监控 |
| MySQL 故障 | 登录/刷新失败 | 主从、重试、告警 |
| JWT 密钥泄露 | 可伪造 Token | 环境变量、定期轮换 |
| Refresh Token 泄露 | 会话被劫持 | 轮换、重放检测、HTTPS |
| Access Token 无法立即撤销 | 15 分钟窗口 | 黑名单或缩短 TTL |
| 表数据增长 | 查询变慢 | 定时清理 |
| 代码重复 | 新旧账号模块并存 | 后续迁移并删除旧代码 |

## 5. 面试讲述建议

可以按以下顺序讲：

1. **背景**：原项目是平铺三层，鉴权没接线，简历里的双 Token 实际没有。
2. **DDD 改造**：账号模块按 domain/application/infrastructure/interfaces 分层，组合根注入。
3. **双 Token**：Access 15 分钟、Refresh 7 天，刷新轮换，旧 Token 重放撤销 Family。
4. **并发安全**：`RevokeIfActive` 条件更新，保证并发刷新只有一个成功。
5. **鉴权接线**：JWTAuth/SoftJWTAuth 挂到路由，移除 MockAccountID。
6. **限流**：Redis Lua 令牌桶，原子扣减，fail-open。
7. **前端**：401 自动刷新，单飞 Promise 合并并发刷新。
8. **边界**：Access Token 撤销窗口、刷新记录清理、旧模块迁移。
9. **下一步**：推拉结合 Feed、热榜衰减、缓存加固、MQ 死信、WebSocket。

一句话总结：

> 这次改造把“简历里写了但代码里没有”的双 Token、JWT 鉴权、令牌桶限流真正落地，并用 DDD 分层把账号模块从“能跑”提升到“可讲清、可测试、可扩展”。
